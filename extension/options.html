Resume Builder server

The bot uses your Resume Builder web app for AI, PDFs and saving bids to Supabase. Use http://localhost:3000 while npm run dev runs, or your Vercel URL.

Job sites

The board the bot reads jobs from (you can also switch it in the side panel). Set your filters (role, Remote, Past 24 hours…) on the site itself; the bot also checks remote and posting age. On HiringCafe the bot hovers each job box and clicks Apply Directly.

Personal details

Typed into application forms. Stored only in this browser. Password, SSN and date of birth are never sent to the AI: it sees placeholders, and the real values are typed straight into the page.

Where bid files are saved

Each bid gets a folder <date>/<id>_<Company>/ with the resume PDF, cover letter PDF, resume.json, job.txt and cover_letter.txt, like the desktop app. The Resume Builder server writes them, so this works when the server runs on this PC (npm run dev). Leave it empty to keep files in Supabase Storage instead.

History

The bot remembers which jobs it already handled (and the server checks Supabase too), so it never applies twice.

Saved answers

Standard questions (contact details, work authorization, sponsorship, EEO, "how did you hear") are answered from My info without the AI. Other screening questions the AI answered once are saved here and reused on later applications, so they cost nothing the next time. Job-specific questions ("Why this company?") are never reused.

AI provider

Saved on the server (shared with the Resume Builder web app). The proxy set in the web app applies here too.

Reading application pages (filling the forms) can use a different provider, for example resumes on Claude and forms on OpenAI.

AI usage

Tokens and cost of every AI call (resume, cover letter, reading application pages), saved in Supabase. Cost uses the prices below.

Prices (US$ per 1 million tokens)

Built-in prices cover common models. Add or correct a model here as JSON, for example {"gpt-5.5": {"input": 1.25, "cached": 0.125, "output": 10}}. Your entries override the built-in ones. Models without a price still have their tokens counted.
